And So It Begins

Day 002 | Sunday | August 23, 2026

I don't remember exactly how I decided to kick off this year-long project to get a fully green GitHub bar. But the first action item, at 11:07 p.m. on Friday, was to ask Claude:

Give me 100 micro dev projects (HTML, CSS, and Javascript only) to keep my Github going. I want to code every day for a year. Each should be completeable in a single sitting or no more than a week.

The next prompt was to expand the list to 365 projects. I refined that list a bit and then went to bed. I started on the actual project Saturday at noon.

Day 001

The first thing I did was ask Claude Code (I use the VS Code IDE) to create a game of Rock. Paper. Scissors. Lizard. Spock. It did the job. I didn't love the UI, but the thing worked. I didn't even have to explain the rules. At this point, I thought, great, I'll learn how to use Claude Code better as I do this, which will help things at work.

So then I asked Claude to create a landing page for the repo. I figured I would deploy to GitHub Pages and have a single spot where the micro-projects can be viewed. This decision led to me firing Claude. The UI looked fine, if generic, but I figured I could go in and edit the files to look the way I wanted. But when I got into the back-end, the code was overly verbose and disorganized. This had me going back and checking the JS for the game, and yep, same there. So I'll redo that one eventually.

And look, I know that Skills exist. And for work, I will probably use this knowledge to dig more into how Skills operate. But when I'm coding for fun … not worth it to me.

And that's what this is: Coding. For. Fun.

So I stopped using Claude, scrapped all the code it had written, and started over. I used Claude chat to help me narrow down the fonts I wanted. I landed on Recursive (a monospace font with interesting shapes) and Public Sans (the open source font that government websites use).

Then I coded, by hand, for nearly six hours, with breaks for food and unpacking. I decided to serve up the site header and footer across the project with the app.js file. The theme.js file detects system light or dark mode and is render-blocking.

I also started noting, in colophon.md, everywhere Claude wrote something in this repo. The main thing it did on Day 001 was create a CSS file (theme.css) with every HTML element in it, which I'm now using as my CSS boilerplate.

At 8:30 p.m., I shut things down and fell asleep to the end of Project Hail Mary on the TV, with music in my headphones.

4 commits.

Day 002

I worked on this for an hour before Mass, then a couple more hours Sunday evening. The header, hero, and footer for the landing page are finally done, and the navigation is responsive. Claude helped with that part — I wrote the JS for the mobile hamburger nav myself and asked it to check my work when it didn't fire correctly, and it edited that section of app.js.

I don't know why I have such a hard time with JavaScript. Actually, I do. I just don't write it nearly as often as HTML and CSS, and it feels a little more loosey-goosey to write, in my opinion.

It finally occurred to me why I'd want to embed fonts into the CSS file, so I did that. Wasn't hard. I also started the boilerplate for project write-ups, including this log.

It made sense to me, as a web developer, to start this year-long project by building a webpage for it — if I'm going to create 365 micro-projects in one GitHub repo, shouldn't I deploy on GitHub Pages to share it with friends, with a landing page to link to each one? Well, yes. But also, this should not have been my first project. I realized that on Sunday night, having spent at least eight hours on this one "micro"-project. So I decided, at 10:40 p.m., to set an MVP for myself before starting each future project — a good reminder, from a project-management standpoint, to spend more time planning rather than jumping straight in.

Basically, the coding goes faster when the UX work happens first. Since I'm my only user, I'll assume my own needs are paramount in the design, but accessibility still matters most of all, since I'm trying to get more fluent in WCAG standards. That's another thing I'm learning here that carries over directly to work.

5 commits today.
